# SANAD — Render + Keycloak deployment runbook

Status: deployment blueprint prepared; not deployed or live-verified.
Production gate: CLOSED.
Scope: research PoC using synthetic data only.

## Topology

- `sanad-keycloak`: public Render Web Service, Keycloak 26.4.2 production mode.
- `sanad-keycloak-db`: managed PostgreSQL database, private connection.
- `sanad-demo`: Flask API Web Service.
- Public issuer: `https://sanad-keycloak.onrender.com/realms/sanad-lab`.
- API-to-Keycloak introspection: Render private network hostname and port injected as `KEYCLOAK_INTERNAL_HOSTPORT`; the API constructs the internal introspection URL.
- Both services share `OIDC_CLIENT_SECRET` from the Render environment group.

The public issuer must exactly match the `iss` claim returned by Keycloak. The API uses the injected private host/port only for back-channel introspection. Do not change the public issuer to the private hostname. Both services are placed in Frankfurt; Render private networking is region-scoped.

## Cost and region

The blueprint selects Frankfurt and non-free service/database plans because Keycloak requires persistent storage and an always-on production service. Review current Render pricing and the selected database plan in the Render dashboard before applying. This repository change does not create resources or incur charges.

## Required dashboard actions

1. Connect the GitHub repository to Render and create a Blueprint deployment from branch `fix/sanad-p0-security-baseline`.
2. Review the Blueprint diff and costs. Do not apply until the service and database plan are acceptable.
3. In the `sanad-oidc-shared` environment group, retain the generated `OIDC_CLIENT_SECRET`; never copy it into GitHub.
4. Set `KC_BOOTSTRAP_ADMIN_PASSWORD` on the Keycloak service using a password manager-generated random secret of at least 32 characters. Do not put it in this repository, issue comments, build arguments, or chat.
5. Apply the Blueprint and wait for Keycloak `/health/ready` to pass.
6. Open the Keycloak public hostname over HTTPS. Complete first administrator sign-in, enroll MFA, create named admin accounts, and verify recovery. Rotate/disable bootstrap access after named admin access is proven.
7. Create realm `sanad-lab`, confidential OIDC client `driver-wallet-api`, and configure its client secret to the generated shared `OIDC_CLIENT_SECRET`. Enable service account only if a machine-to-machine use case requires it. Do not enable Direct Access Grants or Implicit Flow.
8. Add an audience mapper for `driver-wallet-api`; configure the API audience claim and narrowly scoped `wallet:read` authorization. Verify the introspection response includes exact issuer, audience, subject, active boolean and scope claims.
9. Confirm the API service uses the same shared secret and the exact public issuer. Keep the private introspection URL internal.
10. Restrict Keycloak administration to authorized operators. Do not expose master realm administration to application users.

## Required live verification

Record timestamp, deployment IDs, commit SHA, request/response status, and sanitized evidence (never tokens or secrets):

- OIDC discovery reachable over HTTPS; issuer exactly equals configured issuer.
- Authorized test client obtains a token using Authorization Code + PKCE for a human user, or Client Credentials for an explicitly authorized machine identity. No Resource Owner Password Credentials / Direct Access Grants.
- Correct audience and scope accepted.
- Missing, malformed, expired, revoked, wrong-issuer and wrong-audience tokens rejected.
- Insufficient scope rejected with 403; introspection outage fails closed.
- Revoke test token using the supported Keycloak revocation/logout mechanism and verify subsequent introspection reports inactive.
- MFA enforced for administrator accounts.
- PostgreSQL persistence survives service restart and backup/restore is demonstrated.

A successful discovery or a single HTTP 200 is not evidence that token revocation, expiry, MFA, RBAC, recovery, or production security has passed.

## Important implementation boundaries

- The Render Blueprint provisions infrastructure only when applied in the Render account. It does not create the realm/client/roles automatically.
- The shared client secret is generated by Render. The operator must set the same value in the Keycloak confidential client and the API environment without exposing it.
- The Blueprint uses the expected `sanad-keycloak.onrender.com` service hostname. Verify the actual assigned hostname after resource creation; if it differs, update `KC_HOSTNAME` and `KEYCLOAK_ISSUER` consistently, then redeploy. Keycloak listens on Render's expected HTTP service port 10000. Health and metrics remain on Keycloak's management interface (port 9000); they are not configured as public Render health paths.
- Keycloak's public service endpoint is required for browser-based OIDC redirects. Keep database and API introspection traffic on private connections where supported.
- The CI integration test uses an isolated confidential service-account client with Client Credentials; Direct Access Grants are disabled. This validates machine-client introspection and API authorization only, not human Authorization Code + PKCE, MFA, passkey enrollment, or recovery.
- No admin UI, WebAuthn enrollment flow, recovery flow, blockchain anchoring, or production wallet integration is implemented.
- No live Render deployment, real account creation, secret configuration, or token lifecycle test is claimed by this commit. The API accepts an injected Render private host/port for introspection; local Compose continues to use the issuer-derived endpoint.
